feat(email): Implémentation de la file d'attente email avec BullMQ

## Résumé
Implémentation d'un système de file d'attente email asynchrone utilisant BullMQ et Redis pour améliorer les performances et la fiabilité de l'envoi d'emails dans l'application.

## Fonctionnalités
- File d'attente email avec BullMQ
- Worker asynchrone pour traiter les emails
- Intégration avec le système d'email existant
- Fallback automatique vers l'envoi direct si Redis n'est pas disponible
- Gestion des erreurs et retry automatique
- Scripts de test et de nettoyage

## Fichiers modifiés (3)
1. lib/email.ts : Intégration de la queue email avec fallback
2. package.json : Ajout de la dépendance bullmq
3. package-lock.json : Mise à jour des dépendances

## Fichiers créés (7)
1. lib/email-queue.ts : Configuration de la queue BullMQ
2. lib/email-queue-sender.ts : Fonctions wrapper pour ajouter des emails à la queue
3. workers/email-worker.ts : Worker pour traiter les jobs email
4. scripts/start-email-worker.ts : Script pour démarrer le worker
5. scripts/test-email-queue.ts : Script de test de la queue
6. scripts/test-worker-logs.ts : Script de test avec logs détaillés
7. scripts/clean-failed-jobs.ts : Script pour nettoyer les jobs échoués

## Détails techniques
- Utilisation de BullMQ pour la gestion de la queue
- Connexion Redis avec maxRetriesPerRequest: null (requis pour BullMQ)
- Création dynamique du transporter email à chaque job
- Gestion des credentials email avec vérification au démarrage
- Retry automatique avec backoff exponentiel
- Limitation du débit (10 emails/seconde max)
- Support de 5 jobs en parallèle
